# Milestone 4 Optimization Report

## Reproducible Global Retrieval Benchmark

Empirical benchmark measurements generated by `scripts/run_retrieval_experiment.py` across 15 evaluation queries (13 answerable queries + 2 out-of-domain knowledge gap queries) searching against a 100% global, unfiltered corpus combining all 5 committed repository sample documents (HR, Technology, Finance).

- **Artifact File**: `docs/results/m4_retrieval_experiment.json`
- **Embedding Model**: `all-MiniLM-L6-v2` (384-dimensional dense vectors)
- **Search Scope**: Global corpus vector search (NO pre-filtering by domain)

## Empirical Metric Definitions

- **Recall@1**: Percentage of answerable queries where relevant ground-truth evidence appears at rank 1.
- **Recall@3**: Percentage of answerable queries where relevant evidence appears within top 3 chunks.
- **Recall@5**: Percentage of answerable queries where relevant evidence appears within top 5 chunks.
- **MRR (Mean Reciprocal Rank)**: Average reciprocal rank ($1 / \text{rank}$) of the first relevant chunk.
- **Hit Rate**: Percentage of answerable queries yielding relevant evidence within configured Top-K depth.
- **Avg Retrieval Latency**: Mean time in milliseconds to embed query and rank global corpus chunks.

## Benchmark Analysis & Baseline Selection Rationale
- **Observational Findings**: Config C (700 tokens / 70 overlap / Top-K=7) achieved the highest overall recall (100.0% Recall@3/5, MRR 0.9103) because larger token windows retain broader sentence context.
- **Operational Choice**: Config B (500 tokens / 50 overlap / Top-K=5) is retained as the operational baseline because it matches the application's configured default settings, achieving strong recall (92.3% Recall@3/5) while reducing total prompt token overhead for LLM generation. The benchmark results are observational and do not by themselves establish absolute statistical superiority across all query types.
